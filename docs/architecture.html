Architecture overview

Factory Inventory Management System

A two-tier demo app: a Vue 3 single-page app talks over HTTP to a FastAPI service that serves read-only mock data loaded from JSON files into memory. There is no database, no auth backend, and no persistence.

System architecture

Two local processes. The browser loads the SPA from Vite on :3000, then calls the API on :8001 directly (CORS is open; there is no Vite proxy).

Data flow: changing a filter

The global filter bar is the main interaction. Here is what happens when a user picks a warehouse on the Dashboard.

  1. FilterBar writes shared state

    FilterBar.vue sets selectedLocation. The refs in useFilters.js are declared at module scope, so every view that calls useFilters() sees the same values.

  2. The active view's watcher fires

    Dashboard.vue watches all four filters and calls getCurrentFilters(), which maps UI names to API names (Location → warehouse, Period → month).

  3. api.js builds the request

    Parameters set to "all" are dropped. Dashboard fires four requests in parallel with Promise.all: summary, orders, inventory and backlog.

  4. FastAPI filters in memory

    apply_filters() matches warehouse exactly and category/status case-insensitively. filter_by_month() expands Q1-2025-style values through a hard-coded QUARTER_MAP and substring-matches order_date.

  5. Pydantic validates the response

    List endpoints declare response_model, so the payload is checked against InventoryItem, Order and so on. Summary, spending and report endpoints return plain dicts.

  6. The view re-renders

    Responses land in refs such as allOrders and inventoryItems. KPIs, charts and tables are computed properties that update automatically.

Things to know

Found while reading the code and checking it against the running API.

Watch
Writes live in memory only

Tasks, purchase orders and restocking orders are held in server memory and reset when the server restarts. That keeps the demo stateless, but nothing survives a restart.

Watch
Backlog view is not routed

views/Backlog.vue exists but is intentionally not registered in main.js. Backlog data is shown on the Dashboard instead.

Watch
Backlog count ignores filters

total_backlog_items in the dashboard summary can't be filtered: backlog items have no warehouse or category, and their SKUs aren't in inventory.json to join against.

Watch
API base URL is hard-coded

api.js points at http://localhost:8001. Every view now goes through it, so this is the one place to change.

Note
Demo-grade security

CORS allows all origins with credentials, and the user profile is a client-side mock. That's fine for a local demo, not for deployment.

Running it

Swagger docs are served at http://localhost:8001/docs.

# Backend (port 8001)
cd server
uv run python main.py

# Frontend (port 3000)
cd client
npm install && npm run dev
# Backend tests
cd tests
uv run --project ../server pytest -v

# Regenerate orders.json only
cd server
uv run python generate_data.py
